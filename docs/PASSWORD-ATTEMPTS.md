# 浏览器端每日密码错误限制

2026-10-26 按用户要求保留浏览器端解密，为加密内容增加本地每日错误次数限制。

- 每篇文章或相册分别计数。前 5 次输错仍可继续，第 6 次输错后，当天禁用密码输入与提交。
- 按访客浏览器当地时间每天凌晨 04:00 自动恢复；00:00 至 03:59:59 仍属于前一轮。页面保持打开、休眠唤醒或重新切回标签页时也会重新核对。使用日历时间计算，适应夏令时，既不在午夜重置，也不是从第 6 次错误起等待 24 小时。
- localStorage 键为 `firefly:password-failures:v1:` 加当前 pathname。记录只包含 `day` 与 `failures`，不保存输入的密码。
- `day` 为当前 04:00 计数周期开始的当地日期。2026-10-27 从午夜重置改为凌晨 04:00；首次更新时，凌晨已有的旧版当日记录会迁入当前周期，保留错误次数并在 04:00 正常释放。
- 正确密码不增加次数，也不清空当日已有错误次数；空输入、失效的自动会话缓存及非密码错误不计数。成功密码的 sessionStorage 缓存沿用原实现。
- 每次验证期间禁用重复提交。支持 Web Locks 的浏览器在同源同篇文章的标签页之间串行验证，并通过 storage 事件同步锁定。
- 锁定后显示本地 04:00 重置时间和倒计时；倒计时仅前台更新，不逐秒向屏幕阅读器播报。离开页面会清理监听和定时器。
- 若浏览器拒绝读写存储，退回本次页面会话的内存计数，并明确提示刷新后的持久性限制；存储失败不会把正确解密误判为错误密码。

这是本地浏览器的界面限制。清理站点数据、更换浏览器、改变设备时间或直接处理公开密文仍可绕过，不提供服务端限流或账号权限验证。

验证覆盖：第 5/6 次边界、刷新保留、跨标签同步与并发、每篇独立、跨零点保持锁定、04:00 恢复、凌晨计数与旧记录迁移、夏令时切换日期、第 6 次输入正确密码、重复提交、环境错误及存储受限等情形。
